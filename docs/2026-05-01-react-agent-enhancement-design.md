# ReAct Agent 能力增强路线图

**日期**: 2026-05-01

**状态**: 已批准

---

## 1. 概述

本文档规划了 ReAct Agent 的分阶段增强路线，目标是从基础 ReAct 循环逐步升级为具有自我反思、长记忆、多模型协作和规划能力的智能 Agent 系统。

**当前基线**：
- `ReAct.py`: 基础 ReAct 循环实现
- 支持工具：`calculator`, `search`
- 模型支持：Ollama 接口，支持多种本地模型

---

## 2. 阶段划分总览

| 阶段 | 名称 | 预计工期 | 依赖关系 |
|------|------|----------|----------|
| 阶段 0 | 基础设施准备 | 1-2 天 | - |
| 阶段 1 | 更多工具 | 2-3 天 | 阶段 0 |
| 阶段 2 | 自我反思 | 2-3 天 | 阶段 1 |
| 阶段 3 | 长记忆 | 2-3 天 | 阶段 2 |
| 阶段 4 | 多模型协作 | 3-4 天 | 阶段 1-3 |
| 阶段 5 | 规划能力 | 3-4 天 | 阶段 4 |

## 3. 阶段 0：基础设施准备

### 3.1 目标
为后续扩展提供统一的代码结构基础，实现插件式架构。

### 3.2 实施内容

**Tool 基类设计**：
```python
class Tool(ABC):
    name: str
    description: str
    def execute(self, input: str) -> str: ...
```

**Agent 基类设计**：
- 提取通用 Agent 循环逻辑
- 定义标准接口供子类扩展

**工具注册机制**：
- 装饰器方式：`@register_tool(name="xxx")`
- 支持运行时动态注册

### 3.3 验收标准
- 新增工具只需实现 `Tool` 接口并注册
- 无需修改核心 Agent 代码

---

## 4. 阶段 1：更多工具

### 4.1 目标
扩展工具生态，让 Agent 能处理更丰富的任务。

### 4.2 工具类型

| 类型 | 工具示例 | 功能描述 |
|------|----------|----------|
| 信息获取 | `web_search`, `wikipedia` | 搜索网页内容 |
| 文件操作 | `file_read`, `file_write` | 读写本地文件 |
| 代码执行 | `code_interpreter` | 运行 Python/Shell 代码 |
| 外部服务 | `weather`, `email` | 调用第三方 API |

### 4.3 实现要点

**工具接口规范化**：
- 每个工具有 `name`, `description`, `parameters` 定义
- 让模型能理解工具用途并正确调用

**工具选择策略**：
- 在 System Prompt 中描述所有工具
- 模型根据任务描述自主选择工具
- 可选：添加工具选择推理过程

**安全考虑**：
- 代码执行工具需要沙箱隔离
- 文件操作需要路径限制
- 敏感操作需要确认机制

### 4.4 验收标准
- 至少新增 3 种类型工具（信息获取、文件操作、代码执行）
- Agent 能根据任务描述正确调用工具

## 5. 阶段 2：自我反思

### 5.1 目标
Agent 能评估输出质量，发现错误时主动修正。

### 5.2 核心机制

**角色分离**：
- `Actor Agent`：执行具体任务
- `Reviewer Agent`：评估 Actor 输出

**反思触发条件**：
- 任务执行失败
- 输出置信度低于阈值
- 连续 N 次尝试未成功

**修正循环**：
```
Actor 执行 → Reviewer 评审 → 通过? → 结束
              ↓ 否
         Actor 修正 → 重复
```

### 5.3 实现要点

**Reviewer Prompt 设计**：
- 检查正确性：结果是否准确
- 检查完整性：是否回答了所有子问题
- 检查效率：是否有更简单的解决方案

**失败回退策略**：
- 最大重试次数限制
- 记录失败原因用于后续改进
- 可选：尝试不同工具或方法

### 5.4 验收标准
- Reviewer 能识别常见的错误类型
- Agent 失败后能进行至少 1 次自我修正
- 修正后成功率有明显提升

## 6. 阶段 3：长记忆

### 6.1 目标
实现跨会话的知识积累和经验复用。

### 6.2 记忆层次

```
┌─────────────────────────────────────────┐
│            长期记忆 (Long-term)          │
│         持久化知识库，跨会话              │
├─────────────────────────────────────────┤
│            中期记忆 (Mid-term)           │
│          本次会话的重要信息               │
├─────────────────────────────────────────┤
│            短期记忆 (Short-term)         │
│         当前对话的上下文                  │
└─────────────────────────────────────────┘
```

### 6.3 实现要点

**记忆写入**：
- 从对话中提取有价值的信息
- 工具使用经验、成功/失败模式
- 格式：结构化条目 + 时间戳

**记忆检索**：
- 根据当前任务计算 relevance
- 召回 top-k 相关记忆
- 注入到 context 中

**记忆压缩**：
- 定期汇总合并低价值记忆
- 防止 context 膨胀
- LRU 或基于重要性的淘汰策略

**存储方式**：
- 文件存储（JSON/SQLite）用于初期
- 可扩展为向量数据库（如 Chroma）

### 6.4 验收标准
- Agent 能记住历史会话中的关键信息
- 相似任务可以复用之前的经验
- 记忆检索准确率 > 70%

---

## 7. 阶段 4：多模型协作

### 7.1 目标
实现多个专业 Agent 协同工作，处理复杂任务。

### 7.2 角色设计

| 角色 | 职责 | 输入输出 |
|------|------|----------|
| `Planner` | 分析任务，分解为子任务 | 输入：复杂任务；输出：任务计划 |
| `Executor` | 执行具体子任务，调用工具 | 输入：子任务；输出：执行结果 |
| `Critic` | 评审执行结果，给出反馈 | 输入：结果；输出：通过/修改建议 |

### 7.3 协作模式

**串行模式**：
```
Planner → Executor → Critic → Executor → ... → 最终结果
```

**并行模式**：
```
        ┌─ Executor A → Critic A
Planner ─┼─ Executor B → Critic B
        └─ Executor C → Critic C
                ↓
            汇总结果
```

**层次模式**：
- 高层 Agent 协调多个低层 Agent
- 子 Agent 处理特定领域任务

### 7.4 实现要点

**Agent 间通信**：
- 定义标准 `Message` 格式
- 消息类型：`task`, `result`, `feedback`, `control`
- 可选：消息队列或共享黑板

**协作策略**：
- 由主 Agent 控制流程
- 定义清晰的交接协议
- 处理 Agent 间的冲突

### 7.5 验收标准
- 至少实现 3 种角色的协作
- 复杂任务能正确分解为子任务
- 各 Agent 能有效通信并整合结果

---

## 8. 阶段 5：规划能力

### 8.1 目标
让 Agent 能处理需要多步骤规划的复杂任务。

### 8.2 核心能力

**任务分解**：
- 将复杂问题拆分为可执行的子任务
- 识别子任务间的依赖关系
- 确定执行顺序

**进度跟踪**：
- 记录已完成的步骤
- 标记当前执行位置
- 处理部分失败的情况

**动态调整**：
- 根据执行结果调整后续计划
- 失败时尝试替代方案
- 发现新信息时更新计划

### 8.3 实现要点

**Task 结构**：
```python
class Task:
    id: str
    description: str
    dependencies: list[str]  # 前置任务 ID
    status: Pending | Running | Done | Failed
    result: Any
```

**计划执行引擎**：
- 按依赖顺序调度任务
- 支持并行执行独立任务
- 处理任务失败和超时

**回溯机制**：
- 记录每个决策点
- 失败时尝试其他路径
- 记录已尝试的路径避免重复

### 8.4 验收标准
- 能处理至少 5 步的复杂任务
- 任务分解准确率 > 80%
- 能在执行失败时进行合理的路径调整

---

## 9. 技术债务与扩展点

### 9.1 后续可扩展方向
- **工具学习**：Agent 能学会使用新工具
- **持续学习**：从反馈中不断改进
- **多模态**：支持图像、音频输入
- **分布式**：多个 Agent 实例协同

### 9.2 潜在风险
- Context 膨胀影响性能 → 需要记忆压缩
- 工具选择错误 → 需要更多示例训练
- 多 Agent 通信开销 → 需要优化协议
